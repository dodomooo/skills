# 需求文档标准模板

生成需求文档时，严格遵循以下模板结构。

---

# {文档标题}

| 属性 | 值 |
|------|------|
| 文档编号 | REQ-{YYYYMMDD}-{简短标题} |
| 版本 | 1.0 |
| 创建日期 | {日期} |
| 状态 | 草稿 |

## 1. 引言

### 1.1 目的

描述本文档的目的和预期读者。

### 1.2 背景

描述需求产生的背景、业务驱动因素。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| {术语1} | {定义1} |

### 1.4 参考文档

列出与本需求相关的参考文档。

## 2. 需求概述

### 2.1 产品愿景

一段话概述本次需求要实现的核心目标。

### 2.2 目标用户

描述需求面向的用户角色及其特征。

| 用户角色 | 描述 | 关键诉求 |
|---------|------|---------|
| {角色1} | {描述} | {诉求} |

### 2.3 核心业务流程

用文字或伪代码描述核心业务流程：

```
流程开始
  步骤1: {描述}
  步骤2: {描述}
  如果 {条件}:
    步骤3a: {描述}
  否则:
    步骤3b: {描述}
  步骤4: {描述}
流程结束
```

## 3. 功能需求

### 3.1 功能列表

| 编号 | 功能名称 | 优先级 | 描述 |
|------|---------|--------|------|
| F-001 | {名称} | P0/P1/P2 | {简述} |

### 3.2 功能详细描述

#### F-001 {功能名称}

- **描述**：详细描述功能行为
- **前置条件**：触发此功能需满足的条件
- **业务规则**：
  1. {规则1}
  2. {规则2}
- **输入/输出**：
  - 输入：{描述}
  - 输出：{描述}
- **异常处理**：
  - {异常场景1}：{处理方式}
- **验收标准**：
  1. {标准1}
  2. {标准2}

（对每个功能重复此模板）

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 | 测量方式 |
|------|------|---------|
| {如：页面加载时间} | {如：< 2秒} | {如：P95统计} |

### 4.2 安全需求

列出安全相关的需求。

### 4.3 兼容性需求

列出平台、浏览器、设备等兼容性要求。

### 4.4 可用性需求

列出易用性、可访问性等要求。

### 4.5 其他约束

列出技术、时间、资源等约束条件。

## 5. 数据需求

### 5.1 数据模型

描述关键数据实体及其关系：

```
实体: {名称}
  字段1: {类型} - {说明}
  字段2: {类型} - {说明}

关系: {实体A} -> {实体B} ({关系类型})
```

### 5.2 数据迁移

如涉及数据迁移，描述迁移方案。

## 6. 接口需求

### 6.1 外部接口

描述与外部系统的交互接口。

### 6.2 内部接口

描述与内部模块的交互接口。
