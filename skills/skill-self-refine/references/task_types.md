# Task Types

任务类型识别规则。Orchestrator 根据用户输入特征自动判断任务类型。

## 类型 1: 创建新 Skill

**触发特征（满足任一即可）：**
- 用户描述了需求但未指定已有 Skill 路径
- 用户说 "创建" / "新建" / "写一个" / "帮我做一个" + Skill 相关描述
- 用户指定的路径不存在

**示例:**
- "帮我创建一个处理 CSV 格式转换的 Skill"
- "我想写一个能自动生成 PPT 的 skill"
- "新建一个 code review 的 skill，放在 ~/skills/code-review/"

**流水线:** 创建 → 产物验证 → 回归守卫(跳过) → 人工门禁 → 发布

## 类型 2: 改进已有 Skill

**触发特征（满足任一即可）：**
- 用户指定了已有 Skill 路径 + 改进意图关键词
- 关键词: "改进" / "优化" / "fix" / "修" / "调整" / "完善" / "enhance" / "improve"

**示例:**
- "优化 ~/skills/csv-tool/ 这个 skill"
- "fix 一下 skill-creator 的触发描述"
- "改进 my-skill 的评测流程"

**流水线:** 备份 → 改进 → 产物验证 → 回归守卫 → 人工门禁 → 发布

## 类型 3: 回归检查

**触发特征（满足任一即可）：**
- 用户指定已有 Skill 路径 + 检查意图关键词（无改进意图）
- 关键词: "检查" / "回归" / "验证" / "跑一下测试" / "看看有没有退化"

**示例:**
- "检查一下 csv-tool 有没有退化"
- "回归验证 ~/skills/my-skill/"
- "跑一下 skill-creator 的测试看看结果"

**流水线:** 评测 → 产物验证 → 回归守卫 → 输出结果（不发布）

## 边界情况

### 非 Skill 输入
如果用户输入与 Agent Skill 完全无关（普通代码、文档、闲聊等），回复说明 skill-self-refine 的适用范围并拒绝处理。

### 模糊输入
如果无法确定用户意图，主动询问：
- "你想创建新的 Skill，还是改进已有的？"
- "请指定要操作的 Skill 路径"

### 路径歧义
如果用户提到了路径但不确定是否存在，先检查路径再判断任务类型。
